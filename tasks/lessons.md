# Lessons

- YouTube caption and media endpoints can arrive as relative paths on m.youtube responses; always resolve resource URLs against `https://www.youtube.com` before fetching.
- YouTube watch pages can contain multiple `ytInitialPlayerResponse` assignments, including a leading `null`; extract the last decodable JSON object instead of trusting the first marker.
- YouTube caption tracks can still return `200` with an empty body; treat empty caption payloads as an extraction failure and fall back to transcription instead of marking the video unsupported immediately.
- `URLSession.download` temp files arrive with `.tmp` paths; if on-device transcription depends on AVFoundation opening the file, stage the download into a temp URL with the real audio extension first.
- YouTube direct media URLs can resolve from `playerResponse` but still download as blocked, truncated, or otherwise unreadable payloads; validate both the HTTP response and AVFoundation readability before sending files to Speech.
- YouTube watch-page `MWEB` player responses can hand back signed `googlevideo` URLs that all return `403`, while `youtubei/v1/player` with `IOS` or `ANDROID` client contexts can still provide playable audio URLs for the same video; keep a fallback player-client path.
- Some `googlevideo` audio URLs reject full-file downloads and open-ended ranges but succeed with bounded byte ranges; when `clen` is available, download in fixed-size chunks instead of assuming a single request will work.
- For this project, `iOS-only` is a hard product constraint. Do not drift into helper app, local server, or backend proposals unless the user explicitly relaxes that constraint.
- In this XcodeGen setup, bundled app data should be added through `sources` entries with `buildPhase: resources`; assuming a separate top-level `resources` block will be copied can leave runtime catalogs missing.
- When curated lessons reuse a `youtubeVideoID`, do not blindly reopen an existing record. Resync it to the bundled lesson definition first, or stale `unsupported` state and old audio paths will leak back into Practice.
- In a `WKWebView` YouTube embed, do not load local player HTML with `https://www.youtube.com` as the base URL. YouTube expects WebView clients to identify the app via `Referer` and `origin`, so use an app-identifier origin and surface player error codes instead of leaving the raw iframe overlay in the UI.
- Do not interpret every YouTube embed `code 2` as an unembeddable lesson. If the app bootstraps `YT.Player` with an empty placeholder `videoId`, YouTube can reject the player before the real cue/load command runs.
- For this project's embedded YouTube player, prefer the simplest documented `cueVideoById(videoId, startSeconds, quality)` and `loadVideoById(videoId, startSeconds, quality)` calls over richer object payloads, and sanitize timing values before sending them.
- Do not start `translationTask` just because iOS 18 APIs are present. Preflight `Translation.LanguageAvailability` first, or unsupported devices will spam extension errors during normal Practice loads.
- Bundled caption-derived sentence segments can overlap by several seconds later in a video; never use raw `segment.endTime` for looping playback without clamping it against the next segment's `startTime`.
- Curated lessons loaded from `lesson-catalog.json` bypass runtime segmentation entirely. If a bundled sentence reads too long or unnatural, fix or regenerate the catalog entry itself instead of assuming `SentenceSegmentationEngine` is shaping what Practice shows.
- Curated lesson data needs its own quality gate. For bundled shadowing lessons, verify max segment size and strip bracketed noise like `[Music]` so raw caption artifacts do not leak into Practice.
- Do not invent subsegment timings by proportionally slicing one coarse caption window into multiple sentences. If a curated lesson needs finer practice units, anchor them to real transcript snippet timings first and only do small local splits inside those snippet ranges.
- In practice-heavy screens, keep the primary transport controls pinned in a fixed bottom bar. Do not let the most-used buttons drift vertically with variable-height content.
- Dense navigation like a full segment list should not be open by default on a mobile practice screen. Keep it behind an explicit sheet or expansion so the main looping flow stays focused.
- In Practice range mode, never use increment/decrement steppers for sentence-bound selection when the lesson already has discrete segment IDs. Let the user choose start/end directly from the segment list or current sentence.
- Embedded range playback must follow the same sentence-by-sentence progression model as local playback. Do not loop one coarse clip for a multi-sentence range while keeping the UI pinned to a stale sentence.
- On a focused mobile practice screen, do not keep the default large navigation title unless it adds real value. It can waste a full chunk of vertical space before the lesson content even starts.
- In range mode, the authoritative playback anchor is always the `From` sentence. Do not let the last edited bound or last tapped sentence silently become the playback start.
- When a picker sheet edits a current/range sentence index, open it scrolled to the relevant selected row instead of dumping the user at the top of a long lesson list.
- This product no longer depends on on-device audio extraction. With curated lesson metadata and YouTube embed playback, a web app can reproduce the current practice flow cleanly; the unstable part is arbitrary YouTube import, not the practice UX itself.
- In embedded web playback, do not clear the segment-end monitor before restarting a manual `playLoop`. For indefinite looping, the watcher must stay armed across every seek-to-start cycle; only one-shot segment playback should tear the monitor down on completion.
- In Practice, sentence navigation cannot be a pure UI selection change while playback is active. If the learner taps `Previous` or `Next` during single-sentence playback, issue a fresh playback command for that target sentence immediately so the player and visible sentence never drift apart.
- In React state flows, do not issue playback commands for a newly selected sentence in the same handler that mutates the selected index if race-sensitive behavior matters. Commit the new selection first, then fire cue/play from an effect keyed to the committed index so playback cannot reuse a stale sentence anchor.
- In range practice, distinguish between `editing the range bounds` and `manually navigating within the current range`. Bound edits should still normalize playback back to `From`, but user-driven `Previous`/`Next` navigation inside that range should become the immediate restart anchor for the next play action or active playback jump.
- When the user provides a strong visual reference, adapt the product around that visual language consistently instead of only recoloring existing cards. Match the reference at the layout level too: typography, bar structure, card hierarchy, navigation shape, and control emphasis.
- Hidden/default states on a mobile practice screen should collapse vertically. Do not let a concealed transcript card occupy the same height as a revealed reading card; keep it to a compact status-and-action row.
- When the product is meant to feel mobile-first, do not leave desktop layouts fluid by default. Constrain the whole app, including fixed chrome, to one centered phone-width frame unless the user explicitly wants a responsive wide-screen expansion.
- Practice sentence typography should read like dialogue, not a hero banner. Once the app is constrained to a phone-width frame, re-check the sentence card scale and keep long lines comfortably readable.
- After switching to a fixed phone-width shell, re-evaluate typography again in-context. A sentence size that looks balanced on a wider canvas can still feel oversized once the whole app is framed like a mobile screen.
- If a sentence still feels too large after shrinking font-size, reduce weight too. Extra-bold display weights can make dialogue copy read much larger than its numeric font-size suggests.
- Practice sentence cards should not repeat obvious status labels. If reveal/hide state is already clear from the toggle and the presence of text, remove decorative badges like `Shadowing Line` or `Revealed`.
- For Vite apps deployed to GitHub Pages as a project site, production `base` must match `/<repo>/`. If that is missing, asset URLs will resolve to `/assets/...` and the deployed page will load broken files.
- For iframe-based media on the web, autoplay that must continue from a button press should stay inside the original click gesture when possible. If playback is deferred into a later `useEffect`, the browser can treat it as non-user-initiated and require an extra manual tap.
- If React state propagation still sits between a mobile Safari tap and iframe playback, a synchronous state flush alone may not be enough. Provide an imperative player API for gesture-sensitive commands like play/next/previous so the iframe call happens directly in the tap flow.
- On mobile Safari, keep same-video sentence playback inside the existing iframe session. For segment jumps in one lesson, prefer `seekTo` plus `playVideo` over `loadVideoById`, or the YouTube iframe can drop autoplay even though the tap was user-initiated.
- For YouTube iframe queueing on the web, avoid leaning on the legacy third `suggestedQuality` argument for `cueVideoById`/`loadVideoById`. The safer path is the documented object payload `{ videoId, startSeconds }`, especially when chasing mobile-only `error 2` failures.
- If a mobile-only YouTube iframe error persists, simplify the bootstrap too. Initialize `YT.Player` with a real lesson `videoId` from the start and keep constructor `playerVars` minimal instead of stacking optional parameters before the first cue/play command.
- For Safari, same-video playback transport should depend on current player state, not only on video identity. If the iframe is still `UNSTARTED` or `CUED`, prefer `loadVideoById` for the first real play; `seekTo + playVideo` is better reserved for already active same-video playback.
- Cross-origin YouTube autoplay on Safari is not only about which player API method you call. Also set iframe `allow` permissions for autoplay and listen to `onAutoplayBlocked`, or blocked playback can masquerade as a broken custom control flow.
